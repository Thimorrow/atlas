# M001-S02-T02 -- Task Plan

zu konkreten Event-Instanzen eines Datumsbereichs zusammenfuehren; flexible Ziele als

## Files

- Create: `lib/calendar-expand.ts` -- range-basierte Expansion + ISO-Wochen-/Tages-
  Wrapper. Typen `CalendarEvent`, `FlexibleGoal`, `ExpandedRange`. Zeiten auf HH:MM
  normalisiert (Postgres `time` -> HH:MM:SS, s. KNOWLEDGE).
- Create: `app/api/calendar/route.ts` -- GET `?date=YYYY-MM-DD&view=week|day`
  (default week), liefert `ExpandedRange`.

## What this does

`expandRange(startISO, endISO)`: laedt school_blocks + manual_events im Bereich
(date BETWEEN) und alle routines. Pro Tag im Bereich:
- school_blocks des Tages -> CalendarEvent {source:'school', status, room/teacher}.
  (cancelled bleibt drin, T03 wertet es als freie Luecke.)
- manual_events des Tages -> {source:'manual', notes}.
- fixed-Routinen mit `weekday === Wochentag(Tag)` (0=Mo) -> {source:'routine',
  openEnded}. openEnded -> endTime null (Frontend rendert bis Tagesende).
Events je Tag nach startTime sortiert. flexible_goal-Routinen NICHT auf der Timeline,
sondern als `flexibleGoals[]` {targetPerWeek, done:0, remaining} -- done hat in diesem
Slice keine Quelle (Completion-Tracking kommt mit Modul 2), bewusst 0.
`expandWeek(date)` = Mo..So-ISO-Woche um `date`; `expandDay(date)` = nur dieser Tag.
Wochentag/Woche via UTC-Parsing der date-only-Strings (kein TZ-Drift).
